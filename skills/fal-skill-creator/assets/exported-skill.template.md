`fal` below is short for `uv run <this-skill-dir>/scripts/fal.py`. Without uv, run
`pip install "fal-client>=1.0,<2" httpx jsonschema` and use `python3 <this-skill-dir>/scripts/fal.py`. Pass
`--profile <this-skill-dir>/profile` so the bundled profile is used.

## Generate

1. **Read `profile/prompting.md` first.** It has this model's prompt structure, templates with `{slots}`, the
   parameters that matter, and its limitations. Pick the template that fits the request and fill its slots from
   what the user asked for.
2. If the request is vague or the run looks expensive, confirm the final prompt and key settings with the user in
   one line.
3. Run it:
   ```bash
   fal run --profile <this-skill-dir>/profile --prompt "<final prompt>" [--preset NAME] [--set key=value] [--label tag]
   ```
   Local files: `--set image_url=@./file.png`. An earlier run's output: `--from last`, or
   `--set field=from:<run>#<kind>`. Variations: `--batch requests.jsonl`.
4. Check the output yourself (open image files; check video and audio metadata in the manifest) before reporting
   the file paths, the run id, and the cost.

Exit codes: 2 means fix the arguments (`fal schema {{endpoint_id}}`). 3 means the cost needs approval: ask the
user, then rerun with `--yes`. 4 means a key problem (`references/auth.md`). 5 means fal returned an error.
6 means the job is still running: `fal fetch <run_dir>`, and don't resubmit.

## Chaining

Outputs are saved in `./fal-outputs/<date>/<run_id>/` with a `manifest.json`. Other fal-* skills, and this one, can
consume it with `--from`. See `references/pipelines.md`.

## Maintenance

`fal profile refresh <this-skill-dir>/profile` re-fetches the schema and reports drift. To update the runtime,
re-export from fal-skill-creator with `--force`.
